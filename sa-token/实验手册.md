# Sa-Token 实验手册：复刻 mall-swarm 的 Gateway 鉴权边界

本手册按 `mall-swarm` 的路线学习：Gateway 先按白名单、登录类型和权限处理请求，再按 `Path` / `StripPrefix` / `lb://` 转发。`sa-token/demo/` 是 Maven 骨架；下面的代码是**学习者创建**的完整实验文件，不会自动写入 demo。

## 0. 版本和前置条件

**工作目录**：`springcloud-learn/sa-token/demo/`

- Java 17、Spring Boot 2.7.18、Spring Cloud 2021.0.8。
- Redis 在 `localhost:6379`。
- Nacos 在 `localhost:8848`，并有一个已注册的 `nacos-user-service`。

`mall-swarm/master` 是 Boot 3.5 / Spring Cloud 2025，使用 `sa-token-reactor-spring-boot3-starter` 和新 Gateway 配置前缀；本实验是为仓库当前 Boot 2 版本线选择 `sa-token-reactor-spring-boot-starter`，不能混用。

## 1. 验证 Maven 骨架

**工作目录**：`springcloud-learn/sa-token/demo/`

**目标文件**：`springcloud-learn/sa-token/demo/pom.xml`、`springcloud-learn/sa-token/demo/sa-token-gateway-service/pom.xml`，骨架已提供。

**命令**：

```bash
mvn validate
```

**预期**：`BUILD SUCCESS`。

**为什么**：Gateway 是 WebFlux / Reactor 应用，必须使用 `sa-token-reactor-spring-boot-starter`，不能引入 Servlet 专用 starter。Redis DAO 使网关与业务服务实例共享 token / session。

**边界**：本模块 POM 含 `sa-token-jwt` 是为了学习可选模式，不表示应直接切换到 Stateless JWT。先跑通 Redis session，才讨论 JWT 的失效与撤销代价。

## 2. 创建 Gateway 启动类和完整配置

**工作目录**：`springcloud-learn/sa-token/demo/`

**目标文件**：`springcloud-learn/sa-token/demo/sa-token-gateway-service/src/main/java/com/macro/cloud/satoken/SaTokenGatewayApplication.java`（学习者创建）。

**最终内容**：

```java
package com.macro.cloud.satoken;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.cloud.client.discovery.EnableDiscoveryClient;

@EnableDiscoveryClient
@SpringBootApplication
public class SaTokenGatewayApplication {
    public static void main(String[] args) {
        SpringApplication.run(SaTokenGatewayApplication.class, args);
    }
}
```

**目标文件**：`springcloud-learn/sa-token/demo/sa-token-gateway-service/src/main/resources/application.yml`（学习者创建）。

**最终内容**：

```yaml
server:
  port: 9401

spring:
  application:
    name: sa-token-gateway-service
  redis:
    host: localhost
    port: 6379
  cloud:
    nacos:
      discovery:
        server-addr: localhost:8848
    gateway:
      routes:
        - id: user-service
          uri: lb://nacos-user-service
          predicates:
            - Path=/mall-user/**
          filters:
            - StripPrefix=1

sa-token:
  token-name: Authorization
  token-prefix: Bearer
  is-read-header: true
  is-read-cookie: false
  timeout: 2592000
  active-timeout: -1
  is-concurrent: true
  is-share: false
  token-style: uuid
  is-log: false
```

**为什么**：这沿用 mall-swarm 的 `Authorization: Bearer <token>` 和 UUID token 风格。`/mall-user/user/1` 匹配后经 `StripPrefix=1` 变成下游 `nacos-user-service` 的 `/user/1`；`lb://` 由 Nacos Discovery + LoadBalancer 解析，不是 Sa-Token 的能力。

**命令**：

```bash
mvn -pl sa-token-gateway-service spring-boot:run
```

**预期**：Gateway 监听 `9401` 并注册 Nacos；此时尚未加入过滤器，任何可匹配路由的请求都会转发。

**边界**：`StripPrefix=1` 只修改转发路径；它不会鉴权，也不会创建 token。

## 3. 添加 Gateway 全局登录检查

**工作目录**：`springcloud-learn/sa-token/demo/`

**目标文件**：`springcloud-learn/sa-token/demo/sa-token-gateway-service/src/main/java/com/macro/cloud/satoken/SaTokenGatewayConfiguration.java`（学习者创建）。

**最终内容**：

```java
package com.macro.cloud.satoken;

import cn.dev33.satoken.reactor.filter.SaReactorFilter;
import cn.dev33.satoken.router.SaRouter;
import cn.dev33.satoken.stp.StpUtil;
import cn.dev33.satoken.util.SaResult;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class SaTokenGatewayConfiguration {
    @Bean
    SaReactorFilter saReactorFilter() {
        return new SaReactorFilter()
                .addInclude("/**")
                .addExclude("/mall-auth/**")
                .addExclude("/mall-portal/sso/login")
                .addExclude("/mall-portal/sso/register")
                .addExclude("/actuator/**")
                .setAuth(object -> {
                    SaRouter.match("/mall-admin/**", rule -> StpUtil.checkLogin());
                    SaRouter.match("/mall-admin/**", rule -> StpUtil.checkPermission("admin"));
                    SaRouter.match("/mall-user/**", rule -> StpUtil.checkLogin());
                })
                .setError(throwable -> SaResult.error(throwable.getMessage()));
    }
}
```

**为什么**：`SaReactorFilter` 是 Gateway 的全局 Reactor 过滤器；`StpUtil.checkLogin()` 是认证，`checkPermission("admin")` 是授权，二者不能互相替代。白名单仅应放登录、注册、公开商品、文档和健康检查等真正公共路径。

**命令**：重启 Gateway：

```bash
mvn -pl sa-token-gateway-service spring-boot:run
```

然后请求：

```bash
curl -i http://localhost:9401/mall-user/user/1
```

**预期**：无 token 请求在路由前被拦截，返回 Sa-Token 的未登录错误响应，不会访问下游。该示例的 `setError` 尚未将 HTTP status 映射为 401 / 403；生产实现必须根据 `NotLoginException`、`NotPermissionException` 统一响应，不要一律返回 HTTP 200。

**边界**：`/mall-auth/**` 被排除只表示认证服务的登录/刷新入口可达，不代表其余业务服务都可信或可绕过 Gateway。

## 4. 连接真正的登录状态

**工作目录**：`springcloud-learn/sa-token/demo/`

**目标文件**：登录服务中由学习者创建的 `springcloud-learn/sa-token/demo/<login-service>/src/main/java/.../LoginController.java`。该文件不属于当前 Gateway 骨架；需放在与 Gateway **共享同一个 Redis** 的认证服务中。

**最终核心调用**：认证服务验证账号密码后调用：

```java
StpUtil.login(adminId);
String token = StpUtil.getTokenValue();
```

向客户端返回 token，客户端后续请求必须携带：

```http
Authorization: Bearer <token>
```

**为什么**：Gateway 只能读取并校验 Sa-Token 的登录状态，不能凭空创建用户登录。Redis DAO 让认证服务写入的 token / session 被 Gateway 实例读取；多实例不要使用默认内存 DAO。

**命令**：在认证服务登录成功后：

```bash
curl -i http://localhost:9401/mall-user/user/1 \
  -H 'Authorization: Bearer <login-service-returned-token>'
```

**预期**：Gateway 的 `StpUtil.checkLogin()` 通过，完整链路为：

```text
GET /mall-user/user/1
→ SaReactorFilter 读取 Authorization: Bearer token
→ Redis 验证登录状态
→ Path=/mall-user/**
→ StripPrefix=1
→ lb://nacos-user-service
→ Nacos + LoadBalancer 选择实例
→ GET /user/1
→ 响应返回
```

**边界**：本练习使用一个 login type。mall-swarm 对后台管理员使用 `StpUtil`，对商城会员使用独立的 `StpMemberUtil`；两个身份域必须拆开 login type、登录接口和权限模型。

## 5. 对照 mall-swarm 的安全要点

1. `mall-swarm` Gateway 的白名单包含登录、注册、公共首页/商品、文档和监控端点；不要把 `/**` 或整个业务模块加入白名单。
2. OPTIONS 预检和 CORS 是浏览器协商，不是业务登录。显式放行时仍限制实际跨域 origin、method、header。
3. 网关统一鉴权不等于下游天然安全。若服务能被绕过网关访问，使用网络策略、mTLS 或 Sa-Token Same-Token 验证网关到服务的内部调用。
4. 权限不可永久只缓存在 token 中。角色/权限变更、踢人、禁用账号需要让 Redis session / 权限缓存失效。
5. `mall-swarm` 的 `StpMemberUtil` 明确使用 `StpLogicJwtForSimple("memberLogin")`：会员是 JWT Simple 模式，仍需要 Sa-Token DAO；`token-style: uuid` 不能被解读为整个系统已使用 Stateless JWT。
