# Spring Cloud Gateway 实验手册：精确路径、完整文件与验证

本实验复用已经创建好的 Nacos 用户服务：

```text
springcloud-learn/nacos/demo/nacos-user-service
```

先保证 Nacos 和至少一个 `nacos-user-service` 实例已经运行。Gateway 监听 `9201`，后端用户服务默认监听 `8206`。

Gateway 骨架已创建在：

```text
springcloud-learn/gateway/demo/
├── pom.xml
└── gateway-service/
    ├── pom.xml
    └── src/main/
        ├── java/com/macro/cloud/gateway/
        │   └── config/
        └── resources/
```

POM 和依赖已准备好。后续每一步由你在明确指定的目录创建 Java、YAML 文件。


---

## 0. 启动前置服务

### 0.1 启动 Nacos

在 Nacos 安装目录的 `bin/` 下执行：

```bash
sh startup.sh -m standalone
```

检查：<http://localhost:8848/nacos/index.html> 可以访问。

### 0.2 启动第一个用户服务实例

工作目录：

```text
springcloud-learn/nacos/demo/
```

命令：

```bash
mvn -pl nacos-user-service spring-boot:run
```

检查 Nacos 服务列表中存在：

```text
nacos-user-service
```

并直接请求：

```bash
curl http://localhost:8206/user/1
```

必须先确认该请求成功；Gateway 不负责修复下游服务的问题。

## 1. 创建 Gateway 启动类

创建文件：

```text
springcloud-learn/gateway/demo/gateway-service/src/main/java/com/macro/cloud/gateway/GatewayServiceApplication.java
```

完整内容：

```java
package com.macro.cloud.gateway;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.cloud.client.discovery.EnableDiscoveryClient;

@EnableDiscoveryClient
@SpringBootApplication
public class GatewayServiceApplication {

    public static void main(String[] args) {
        SpringApplication.run(GatewayServiceApplication.class, args);
    }
}
```

`@EnableDiscoveryClient` 让 Gateway 注册到 Nacos，并能使用 Nacos 的服务列表。后面使用 `lb://nacos-user-service` 时，依赖这一能力。

## 2. 实验一：YAML 固定 URI 路由

先不用 Nacos 服务发现，目的是单独理解 Route、Predicate、URI。

### 2.1 创建基础 application.yml

创建文件：

```text
springcloud-learn/gateway/demo/gateway-service/src/main/resources/application.yml
```

完整内容：

```yaml
server:
  port: 9201

spring:
  application:
    name: gateway-service
  profiles:
    active: basic

logging:
  level:
    org.springframework.cloud.gateway: debug
```

### 2.2 创建 application-basic.yml

创建文件：

```text
springcloud-learn/gateway/demo/gateway-service/src/main/resources/application-basic.yml
```

完整内容：

```yaml
service-url:
  user-service: http://localhost:8206

spring:
  cloud:
    gateway:
      routes:
        - id: user-by-id-route
          uri: ${service-url.user-service}
          predicates:
            - Path=/user/{id}
```

这条路由的含义：

```text
客户端请求：GET http://localhost:9201/user/1
Path=/user/{id}：匹配成功
目标 URI：http://localhost:8206
下游请求：http://localhost:8206/user/1
```

Gateway 没有修改路径；它只将原始 `/user/1` 拼接到目标服务根地址。

### 2.3 启动与验证

工作目录：

```text
springcloud-learn/gateway/demo/
```

启动：

```bash
mvn -pl gateway-service spring-boot:run
```

验证：

```bash
curl http://localhost:9201/user/1
```

预期：响应内容与直接请求 `http://localhost:8206/user/1` 一致。

再请求：

```bash
curl -i http://localhost:9201/abc/1
```

预期：没有任何 `Path=/user/{id}` 路由匹配；通常得到 404。这里证明 Gateway 是先匹配 Predicate，再转发。

## 3. 实验二：Java RouteLocator 路由

YAML 与 Java 配置可共存。这个实验让 `/user/getByUsername` 通过 Java 路由转发。

创建文件：

```text
springcloud-learn/gateway/demo/gateway-service/src/main/java/com/macro/cloud/gateway/config/GatewayConfig.java
```

完整内容：

```java
package com.macro.cloud.gateway.config;

import org.springframework.cloud.gateway.route.RouteLocator;
import org.springframework.cloud.gateway.route.builder.RouteLocatorBuilder;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class GatewayConfig {

    @Bean
    public RouteLocator customRouteLocator(RouteLocatorBuilder builder) {
        return builder.routes()
                .route("user-by-username-route", route -> route
                        .path("/user/getByUsername")
                        .uri("http://localhost:8206"))
                .build();
    }
}
```

这里的 `uri("http://localhost:8206")` 是目标服务的根地址，不要写成：

```java
.uri("http://localhost:8206/user/getByUsername")
```

因为原始请求路径会继续保留。后者会产生重复路径：

```text
/user/getByUsername/user/getByUsername
```

重启 Gateway 后验证：

```bash
curl "http://localhost:9201/user/getByUsername?username=macro"
```

请求路径保持 `/user/getByUsername`，查询参数 `username=macro` 也会被转发到 8206。

## 4. 实验三：Predicate 路由匹配

这一节使用一个独立 profile，避免与基础路由混淆。

创建文件：

```text
springcloud-learn/gateway/demo/gateway-service/src/main/resources/application-predicate.yml
```

完整内容：

```yaml
service-url:
  user-service: http://localhost:8206

spring:
  cloud:
    gateway:
      routes:
        - id: header-user-route
          uri: ${service-url.user-service}
          predicates:
            - Path=/user/{id}
            - Method=GET
            - Header=X-Request-Id, \d+

        - id: query-user-route
          uri: ${service-url.user-service}
          predicates:
            - Path=/user/getByUsername
            - Query=username
```

使用 profile 启动：

```bash
mvn -pl gateway-service spring-boot:run \
  -Dspring-boot.run.arguments="--spring.profiles.active=predicate"
```

验证 Header Predicate：

```bash
curl -i http://localhost:9201/user/1 -H "X-Request-Id:123"
```

预期：匹配 `header-user-route` 并转发。

```bash
curl -i http://localhost:9201/user/1
```

预期：不匹配，因为缺少 `X-Request-Id`。

验证 Query Predicate：

```bash
curl "http://localhost:9201/user/getByUsername?username=macro"
```

预期：匹配 `query-user-route`。

```bash
curl -i http://localhost:9201/user/getByUsername
```

预期：不匹配，因为缺少 `username` 查询参数。

同一路由的 Predicate 是 AND 关系；例如 Header 路由必须同时满足 Path、Method、Header。

## 5. 实验四：常用 GatewayFilter

创建文件：

```text
springcloud-learn/gateway/demo/gateway-service/src/main/resources/application-filter.yml
```

完整内容：

```yaml
service-url:
  user-service: http://localhost:8206

spring:
  cloud:
    gateway:
      routes:
        - id: strip-prefix-route
          uri: ${service-url.user-service}
          predicates:
            - Path=/user-service/**
          filters:
            - StripPrefix=1

        - id: create-user-route
          uri: ${service-url.user-service}
          predicates:
            - Path=/create-user
            - Method=POST
          filters:
            - AddRequestHeader=X-Gateway-Request, gateway-service
            - RewritePath=/create-user, /user/create

        - id: prefix-path-route
          uri: ${service-url.user-service}
          predicates:
            - Path=/{id}
            - Method=GET
          filters:
            - PrefixPath=/user
```

使用 profile 启动：

```bash
mvn -pl gateway-service spring-boot:run \
  -Dspring-boot.run.arguments="--spring.profiles.active=filter"
```

### 5.1 StripPrefix

```bash
curl http://localhost:9201/user-service/user/1
```

路径变化：

```text
进入 Gateway：/user-service/user/1
StripPrefix=1：/user/1
下游服务：http://localhost:8206/user/1
```

### 5.2 PrefixPath

```bash
curl http://localhost:9201/1
```

路径变化：

```text
进入 Gateway：/1
PrefixPath=/user：/user/1
下游服务：http://localhost:8206/user/1
```

### 5.3 AddRequestHeader 与 RewritePath

```bash
curl -X POST http://localhost:9201/create-user \
  -H "Content-Type: application/json" \
  -d '{"name":"macro","passwd":"123"}'
```

路径和请求头变化：

```text
进入 Gateway：POST /create-user
RewritePath：POST /user/create
AddRequestHeader：X-Gateway-Request: gateway-service
下游服务：POST http://localhost:8206/user/create
请求体：原样转发 {"name":"macro","passwd":"123"}
```

## 6. 实验五：Redis RequestRateLimiter

先启动 Redis：

```bash
redis-server
```

创建文件：

```text
springcloud-learn/gateway/demo/gateway-service/src/main/java/com/macro/cloud/gateway/config/RedisRateLimiterConfig.java
```

完整内容：

```java
package com.macro.cloud.gateway.config;

import java.util.Optional;

import org.springframework.cloud.gateway.filter.ratelimit.KeyResolver;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class RedisRateLimiterConfig {

    @Bean
    public KeyResolver ipKeyResolver() {
        return exchange -> {
            String remoteAddress = Optional.ofNullable(exchange.getRequest().getRemoteAddress())
                    .map(address -> address.getAddress())
                    .map(address -> address.getHostAddress())
                    .orElse("unknown");
            return reactor.core.publisher.Mono.just(remoteAddress);
        };
    }
}
```

创建文件：

```text
springcloud-learn/gateway/demo/gateway-service/src/main/resources/application-ratelimit.yml
```

完整内容：

```yaml
spring:
  data:
    redis:
      host: localhost
      port: 6379

  cloud:
    gateway:
      routes:
        - id: rate-limited-user-route
          uri: http://localhost:8206
          predicates:
            - Path=/user/{id}
            - Method=GET
          filters:
            - name: RequestRateLimiter
              args:
                key-resolver: "#{@ipKeyResolver}"
                redis-rate-limiter.replenishRate: 1
                redis-rate-limiter.burstCapacity: 2
                redis-rate-limiter.requestedTokens: 1
```

启动：

```bash
mvn -pl gateway-service spring-boot:run \
  -Dspring-boot.run.arguments="--spring.profiles.active=ratelimit"
```

连续请求：

```bash
curl -i http://localhost:9201/user/1
curl -i http://localhost:9201/user/1
curl -i http://localhost:9201/user/1
```

预期：前两次可以消耗初始令牌；紧随其后的请求应得到 `HTTP/1.1 429 Too Many Requests`。等待一秒后，令牌补充，可以再次请求。

生产网关位于 Nginx、负载均衡器或 Ingress 后时，不应直接相信 TCP 对端 IP；需要先正确配置可信代理和转发头，否则限流维度会把代理 IP 当用户 IP。

## 7. 实验六：Nacos Discovery 与 `lb://`

先运行 Nacos 用户服务的两个实例：

工作目录：

```text
springcloud-learn/nacos/demo/
```

```bash
mvn -pl nacos-user-service spring-boot:run
mvn -pl nacos-user-service spring-boot:run \
  -Dspring-boot.run.arguments="--server.port=8207"
```

确认 Nacos 服务列表中 `nacos-user-service` 有两个健康实例。

创建文件：

```text
springcloud-learn/gateway/demo/gateway-service/src/main/resources/application-nacos.yml
```

完整内容：

```yaml
spring:
  cloud:
    nacos:
      discovery:
        server-addr: localhost:8848

    gateway:
      discovery:
        locator:
          enabled: true
          lower-case-service-id: true
      routes:
        - id: nacos-user-service-route
          uri: lb://nacos-user-service
          predicates:
            - Path=/api/user/**
          filters:
            - StripPrefix=1
```

启动：

```bash
mvn -pl gateway-service spring-boot:run \
  -Dspring-boot.run.arguments="--spring.profiles.active=nacos"
```

验证：

```bash
curl http://localhost:9201/api/user/1
```

路径和服务发现流程：

```text
/api/user/1
  → Path=/api/user/** 匹配
  → StripPrefix=1
  → /user/1
  → lb://nacos-user-service
  → Nacos 返回 8206、8207 健康实例
  → LoadBalancer 选择一个实例
  → 实际请求 http://<instance>/user/1
```

连续多次请求，观察两个用户服务实例的日志。若只启动一个实例，`lb://` 仍可工作，但无法观察负载均衡。

自动路由也已开启：当 Nacos 中有 `nacos-user-service` 时，Gateway 还可生成默认路径：

```text
/nacos-user-service/**
```

本实验同时写了显式 `/api/user/**` 路由，目的是演示 `StripPrefix` 和 `lb://`。生产环境通常应选择清晰的显式路由规则，避免把所有服务名直接暴露给外部客户端。
